# 双平台设计

使用场景是已经安装官方 HyperFrames 的用户，通过单独启动器临时启用中文。应用更新、安装位置不同和后台重复打开需要被正确处理。

现有 Mac 外壳已经完成真实调试接口验证。为保留原有行为，继续使用 Swift / AppKit，并增加 C# / WinForms Windows 外壳；共用同一份 JavaScript 翻译引擎、词典和模板。代价是分别维护操作系统的应用定位、托盘、进程、单实例和监听端口检查。翻译内容只维护一份，无需为此引入新的 WebView 或在线服务。

定位与启动由操作系统部分处理。启动后验证 loopback 监听与进程归属，读取 CDP 页面列表，只注入 HyperFrames 桌面主页面，再用 MutationObserver 翻译后续文案。HTTP 页面自身的本机服务端口与调试端口可以不同；WebSocket 调试连接必须匹配已验证端口。

Windows 通过当前用户 Mutex / NamedPipe 处理重复打开请求，用户操作排队，定时刷新忙时跳过。Mac 通过应用重开事件和本机分发通知交给已有实例处理。原应用退出后清理旧连接，新进程须重新通过验证。无调试参数时，用户确认正常重启；保存提示及取消均保留，不强制结束原应用。

验证标准：不同安装位置可用、重复打开不新增助手实例、只能连接合法主页面、用户内容与事件保持、正常退出恢复英文、原程序文件不变。Windows 通过一次性 runner 执行原生与官方应用集成验证；实际桌面体验、发布者签名和不同用户环境需继续验证。
